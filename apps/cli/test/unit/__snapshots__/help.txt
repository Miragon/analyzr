## analyzr

Usage: analyzr [options] [command]

analyzr command line: seed, import, list, requeue, delete, amend and pull models, list, export,
answer and act on open questions, list, export and withdraw model amendments, push and pull the
value chain, manage agent tokens and auto-accept rules, bridge MCP over stdio

Options:
  -v, --version                  output the version number
  --url <url>                    analyzr server URL (env ANALYZR_URL, default http://127.0.0.1:7400)
  --token <token>                agent token analyzr_at_… (env ANALYZR_TOKEN)
  --owner-key-file <file>        local owner key file (env ANALYZR_OWNER_KEY_FILE, default
                                 ~/.local/state/analyzr/owner-key)
  -h, --help                     display help for command

Commands:
  health                         check that the server and its database are up
  status [options]               server health and, per project, models by stage, relations and
                                 findings
  import [options] <dir>         import every BPMN file below <dir> into a project (model key: the
                                 one analyzr-import.json pins, else the path); then says what waits
                                 for an agent
  models                         list, requeue, delete, amend and pull a project's models, and their
                                 source-system ids
  questions                      list and export the open questions of a project (list, the
                                 default), add notes (answer) or act on them (outside, link, place,
                                 amend)
  amendments                     list, export and withdraw a project's model amendments
                                 („Ergänzungen“): fields a human set in analyzr, applied to every
                                 import of the model while the source tool leaves them as they were
  token                          manage agent tokens (owner key)
  value-chain                    push and pull the value chain document (.vc.json) of a project,
                                 requeue its placement task
  rules                          manage a project's auto-accept rules (owner key; owner decision
                                 19): agent proposals at or above a confidence, or with --derived
                                 the rule tier's unique calls from derived models of one declared
                                 source, are accepted as the owner's decision
  mcp                            MCP stdio bridge to <url>/mcp with ANALYZR_TOKEN (for Claude
                                 Desktop and other stdio-only clients)
  seed [options] [landscape...]  create one project per eval landscape and import its models
                                 (default: every scored landscape); --value-chains also creates its
                                 golden value chain
  help [command]                 display help for command

## analyzr models

Usage: analyzr models [options] [command]

list, requeue, delete, amend and pull a project's models, and their source-system ids

Options:
  -h, --help                  display help for command

Commands:
  list [options]              list the models: key, stage, head revision, engine, open items
  requeue [options] [key...]  queue the relations task of models again, e.g. after a failed task
                              (owner key or a token with analyzr:write)
  delete [options] <key...>   delete models (owner key): lists them without --yes; partner relations
                              turn missing, uploading a key again revives its model
  external-ids [options]      list each live model's identity in its source system (key, tool id,
                              tool folder) as the newest import declared it, to rebuild a key map
                              (any credential)
  amend [options] <key>       amend one field of a model as a human (owner key): the call target, a
                              message or signal name, a start or end name, or the documentation of a
                              process without one, where an open question names it or it is empty; a
                              new amended revision computed from the uploaded one, which the next
                              import applies again while the source tool leaves the field as it was.
                              Dry run first; prints the effect and the cost
  pull [options] <key>        write a model's BPMN verbatim: the head (amended when amendments
                              apply), or with --original the uploaded revision it is computed from;
                              r<rev> <sha256> on stderr (any credential)
  help [command]              display help for command

## analyzr models amend

Usage: analyzr models amend [options] <key>

amend one field of a model as a human (owner key): the call target, a message or signal name, a
start or end name, or the documentation of a process without one, where an open question names it or
it is empty; a new amended revision computed from the uploaded one, which the next import applies
again while the source tool leaves the field as it was. Dry run first; prints the effect and the
cost

Arguments:
  key                      model key

Options:
  -p, --project <project>  project key or id
  --element <id>           the element whose field is set: its id in the BPMN file
  --call-target <target>   the target of a call activity: a ref, the key of a model with one
                           process, or a unique process name
  --message-name <name>    the name of the message or signal an endpoint references (every element
                           referencing it reads the new name)
  --name <label>           the name of a start or end event
  --documentation <text>   the documentation of a process that has none
  --partner <ref>          with --message-name: the endpoint of another process whose name it is;
                           the proposal between them is accepted as your decision
  --dry-run                print the effect and the cost; record nothing
  --yes                    save even when an agent holds the model's relations task (the new head
                           cancels it, and the agent's work is lost)
  --json                   print JSON
  -h, --help               display help for command

## analyzr questions

Usage: analyzr questions [options] [command]

list and export the open questions of a project (list, the default), add notes (answer) or act on
them (outside, link, place, amend)

Options:
  -h, --help              display help for command

Commands:
  list [options]          the open questions of a project, questions before value chain findings and
                          informational items, each most open decisions first: a table with the
                          primary action and the suggested targets, JSON, or the Markdown or CSV
                          export (any credential)
  answer [options] [id]   record notes as a human (owner key): one with <id> --text, or the
                          filled-in CSV sheet of the export with --from; on a relation or placement
                          the note lands on it; a note leaves the question open
  outside [options] <id>  mark an open question „Liegt außerhalb der Landschaft“ as a human (owner
                          key): the question turns answered; --undo withdraws a mark
  link [options] <id>     answer an open question with a link as a human (owner key): a live
                          proposal between the question's element and the target is accepted, else
                          an accepted manual relation is written
  place [options] <id>    answer an open question with a placement as a human (owner key): the
                          question's process on a step of the value chain or on @outside, or for a
                          step without a process the process on that step; accepted at once
  amend [options] <id>    answer an open question by amending the model as a human (owner key): the
                          field its amend action names, in one new amended revision; without a value
                          it records the action's prefilled one („Meine Ergänzung behalten“). Dry
                          run first; prints the effect and the cost
  help [command]          display help for command

## analyzr rules

Usage: analyzr rules [options] [command]

manage a project's auto-accept rules (owner key; owner decision 19): agent proposals at or above a
confidence, or with --derived the rule tier's unique calls from derived models of one declared
source, are accepted as the owner's decision

Options:
  -h, --help              display help for command

Commands:
  list [options]          list the rules with their head revision and what they accepted, and the
                          system rule
  show [options] <id>     show a rule and its immutable revisions
  add [options]           create a rule (off unless --enable; never retroactive) and print its
                          preview; needs --name, --kind, --tier, --min, or --name and --derived for
                          a rule for derived calls
  edit [options] <id>     save the flags as the next revision of a rule (If-Match on its head)
  enable [options] <id>   enable a rule (a new revision); reports how many open proposals already
                          match
  disable [options] <id>  disable a rule (a new revision); its acceptances stay and remain revocable
  preview [options] [id]  what a rule would have accepted so far (with the precision of the human
                          decisions), would accept now, and the confidence curve (a rule for derived
                          calls: the calls per declared source instead); a saved rule (<id>, changed
                          by flags) or an unsaved one (--kind, --tier, --min, or --derived)
  apply [options] <id>    accept the open proposals a rule's head revision matches: prints the dry
                          run; accepts only with --yes
  revoke [options] [id]   revoke auto-acceptances still in force (by rule, revision, agent, kind or
                          ids): back to review, or obsolete when no proposal remains; a human
                          decision taken since is never touched. Prints the dry run; revokes only
                          with --yes
  pre-trust [options]     the unique calls the rule tier accepted before the trust rule from callers
                          that would be derived today (no engine, an agent token, a declared
                          conversion): list them, send them back to review (--revoke) or keep them
                          accepted (--keep), each model once. Prints the dry run; changes something
                          only with --yes
  help [command]          display help for command

## analyzr rules add

Usage: analyzr rules add [options]

create a rule (off unless --enable; never retroactive) and print its preview; needs --name, --kind,
--tier, --min, or --name and --derived for a rule for derived calls

Options:
  --name <name>               rule name (unique in the project)
  --kind <kind>               relation or placement (never changes)
  --tier <tier>               proposal tier: key, lexical, semantic (placements: lexical, semantic)
  --min <confidence>          minimum confidence, inclusive: 0.9 or 90% (at least 50%)
  --type <type>               relations only: call, message, signal or trigger (any: every type)
  --agent <agent>             only this agent: token id agt_…, token name or principal prn_… (any:
                              every agent)
  --model <llmModel>          only proposals declaring exactly this LLM model (any: every model)
  --ad-hoc                    also ad-hoc proposals (default: pipeline proposals only)
  --no-ad-hoc                 pipeline proposals only
  --note <text>               a note for reviewers ("" removes it)
  --derived <source>          a rule for derived calls (the rule tier’s unique calls from derived
                              models): export, converted or none (no kind declared); fixes kind,
                              tier, type and minimum; never accepts an agent token’s upload
  --converter <name@version>  with --derived converted: the converter exactly as the manifest
                              declares it
  -p, --project <project>     project key or id
  --enable                    enable the rule right away
  --json                      print JSON
  -h, --help                  display help for command

## analyzr seed

                            checkout)

  --json                    print JSON
  -h, --help                display help for command
